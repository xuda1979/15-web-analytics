1 引言
========================================================

1.1 编写目的
　　本手册面向软件使用者与网站管理员，说明 15-web-analytics V1.0 的安装、
配置、日常操作与常见故障处理方法。文中所有命令示例均在 Linux 环境下验证。

1.2 软件简介与适用范围
　　15-web-analytics 是一款“无 cookie、全自托管”的轻量网站访问统计分析软
件。浏览器端嵌入约 1KB 采集脚本后，服务端即可提供访问量、独立访客、跳出率、
访问时长、来源渠道、设备 / 浏览器 / 操作系统 / 国家分布、入口出口页、实时趋
势等指标，并支持按页面、来源、设备筛选，导出 CSV / JSON，自动数据留存与隐私
审计。适用于：个人网站 / 博客、企业内部站点、电商内容页、以及受《个人信息保
护法》约束、需要规避第三方统计与跨境数据的自建站点。

1.3 术语定义
　　· 访问量（visits）：页面浏览量，即事件（pageview）总数；
　　· 独立访客（uniques）：以伪匿名游客键去重的访客数；
　　· 跳出率（bounce rate）：只浏览了一个页面的访问占全部访问的百分比；
　　· 平均访问时长：一个访问内最后一个事件与第一个事件的间隔均值（仅计多页
　　　访问）；
　　· 游客键（guest_key）：IP 与 User-Agent 的 HMAC 加盐摘要，用于近似识别访客，
　　　全程不写 cookie、默认不存明文 IP。

2 安装与卸载
========================================================

2.1 环境要求
　　· 操作系统：Linux / macOS / Windows（Node.js 可运行即可）；
　　· 运行时：Node.js ≥ 22.5.0（需内置 node:sqlite 模块，可从 nodejs.org 或
　　　发行版软件源安装，建议 LTS）；
　　· 硬件：最低 1 核 CPU、256 MB 内存、200 MB 磁盘；推荐 2 核 / 1 GB；
　　· 依赖：运行时仅需 ua-parser-js（npm 自动安装）。

2.2 安装步骤
　　(1) 获取源码：将源码目录（含 package.json、src、public、test）复制或克隆
　　　　到服务器，如 /opt/15-web-analytics；
　　(2) 安装依赖：
　　　　　cd /opt/15-web-analytics
　　　　　npm install
　　(3) （可选）初始化演示数据：
　　　　　npm run seed
　　　　该命令会在 <数据目录>/analytics.sqlite 生成 12 名游客、跨约 60 天、
　　　　约 260 条演示事件，便于先体验仪表盘。
　　(4) 启动服务：
　　　　　npm start
　　　　看到 "15-web-analytics listening on http://127.0.0.1:8787" 即成功。

2.3 首次启动与验证
　　(1) 浏览器访问 http://<服务器IP>:8787/ 查看仪表盘；
　　(2) 访问 http://<服务器IP>:8787/api/health，应返回 {"ok":true,"ts":...}；
　　(3) 访问 http://<服务器IP>:8787/api/audit?format=text 查看隐私审计文本；
　　(4) 将采集脚本嵌入任意页面（见 3.1），刷新后便能在仪表盘看到该次访问。
　　提示：默认可访问系统为 curl / 浏览器；如需对外投放统计，请设置 WA_HOST=
　　0.0.0.0 或置于反向代理之后。数据目录默认在 ./data。

2.4 卸载
　　(1) 停止服务：Ctrl+C 或 kill <进程号>（SIGTERM 触发优雅停机）；
　　(2) 如需保留数据：备份 data/ 目录后直接删除程序目录；
　　(3) 如需完全清除：删除程序目录（含 data/ 下的 analytics.sqlite 与
　　　　.wa_secret 密钥文件）。密钥文件丢失后旧游客键无法还原，历史独立访客
　　　　计数将从新密钥起算——故卸载无重装计划时无需另行处理。
　　(4) 依据安装方式归还资源：systemd/npm 全局安装则执行对应
　　　　`systemctl disable --now` / `npm uninstall -g`。

3 操作说明
========================================================

3.1 采集脚本嵌入（网站侧）
　　在网站每个页面 </body> 前插入一行（可放到公共模板）：
　　　<script defer src="https://<你的域名>:8787/wa.js"></script>
　　脚本会自动采集当前页面路径、来源、标题、屏幕分辨率、语言，并优先使用
　　sendBeacon 上报（页面关闭场景也能送达），不支持时自动回退 XHR。可用
　　data-endpoint 属性指向其他部署：
　　　<script defer
　　　　src="https://analytics.example.com/wa.js"
　　　　data-endpoint="https://analytics.example.com/api/collect"></script>
　　说明：脚本不写 cookie、不含第三方请求，可通过 CSP 配置安全放行。

3.2 仪表盘使用
　　打开仪表盘首页后，自上而下依次为：
　　· KPI 区：总访问量、独立访客数、跳出率、平均访问时长；
　　· 图表区：日 / 周 / 月访问趋势图（点击日期粒度切换）；
　　· 榜单区：热门页面、来源渠道、设备、浏览器、国家 / 地区、操作系统
　　　（各取前 50 名）；
　　· 路径区：进入含“入口页 / 出口页”两个榜单，反映访客从哪些页面进站、
　　　从哪些页面离开。

3.3 时间范围与筛选
　　· 时间范围：URL 参数 days=N（如 /?days=7 看近 7 天），支持 from / to
　　　（ISO 日期）精确指定区间；默认 30 天，最大 3650 天。
　　· 维度筛选：在榜单中点击某页面 / 某来源 / 某设备即可全局联动筛选——KPI、
　　　趋势图与全部榜单（源头、入口出口等）同步按该维度过滤；再次点击取消。
　　　筛选语义：对“入口 / 出口”按访问级过滤（命中筛选的整个访问参与统计），
　　　其余指标按事件级过滤。

3.4 实时统计
　　仪表盘顶部“实时”面板或直接访问 /api/realtime，展示最近 5 分钟（可通过
　　WA_REALTIME_WINDOW_MS 调整）按 1 分钟粒度分组的访问量与独立访客，供线上
　　活动 / 发布版本期间观察即时流量。

3.5 数据导出
　　导出命令均支持以下参数（与仪表盘筛选一致）：
　　· format：json（默认）或 csv；
　　· summary=1：导出汇总报表（各区块与仪表盘一致），否则导出事件明细；
　　· page / source / device：按维度筛选后导出；
　　· days / from / to：时间范围。
　　示例：
　　　# 导出最近 7 天事件明细（CSV，IP 已匿名化）
　　　curl -o events.csv "http://localhost:8787/api/export?format=csv&days=7"
　　　# 导出 /pricing 页面近 90 天汇总 JSON
　　　curl "http://localhost:8787/api/export?summary=1&days=90&page=/pricing"
　　CSV 明细字段：visited_at、guest_key、ip（匿名或空）、path、referrer、
　　ref_domain、title、screen_w、screen_h、lang、country、browser、device、os。

3.6 命令行操作
　　npm run seed　　　　　生成演示数据；
　　npm run collect -- --path=/pricing --referrer=https://example.com
　　　　　　　　　　　　　手动上报一条页面访问（可附加 --sw=1440 --sh=900
　　　　　　　　　　　　　--lang=zh-CN --ip= --ua= 参数）；
　　npm run prune -- --days=30　　删除 30 天前的历史事件并重建统计缓存；
　　npm run privacy-audit　　　　　打印隐私审计摘要。
　　说明：Node 22 下 node:sqlite 仍标记为实验特性，脚本统一加
　　--disable-warning=ExperimentalWarning 抑制告警，不影响功能。

3.7 隐私审计
　　审计报告由 7 项自动检查组成：
　　1. cookies / 标识符：不写 cookie、不签发追踪 ID —— 通过；
　　2. 个人字段：表结构不含姓名 / 邮箱 / 电话 —— 通过；
　　3. 明文 IP 存储：默认不存（WA_STORE_IP=1 时告警）—— 通过/告警；
　　4. 采集脚本体积：限制约 1KB —— 通过；
　　5. 地域粒度：仅地区级，无精确定位 —— 通过；
　　6. 存储驻留：数据全部本地 SQLite —— 通过；
　　7. 数据留存：按 WA_RETENTION_DAYS 自动 / 手动清理 —— 通过。
　　文本输出：
　　　curl "http://localhost:8787/api/audit?format=text"
　　JSON 输出：
　　　curl "http://localhost:8787/api/audit"

4.2 示例配置
　　仅监听本机（默认）：
　　　npm start
　　对外提供服务 + 开启数据留存：
　　　WA_HOST=0.0.0.0 WA_PORT=8787 WA_RETENTION_DAYS=180 npm start
　　使用自定义数据目录与密钥盐：
　　　WA_DATA_DIR=/var/lib/wa WA_HASH_SALT=my-site-secret npm start
　　调紧限流（每 IP 每分钟 30 次）：
　　　WA_COLLECT_RATE_LIMIT=30 npm start
　　强调隐私（禁止明文 IP，双重保险）：
　　　WA_STORE_IP=0 npm start

4.3 数据文件说明
　　data/analytics.sqlite　　　主数据库（WAL 模式，含 events 表 / 聚合缓存 / meta）；
　　data/analytics.sqlite-wal / -shm　WAL 辅助文件（正常停机自动合并）；
　　data/.wa_secret　　　　　 游客键密钥（权限 0600，切勿外泄；备份与数据库同
　　　　　　　　　　　　　　　 在，恢复时二者需一并还原）。

5 故障处理与 FAQ
========================================================

5.1 常见问题排查
　　5.1.1 服务无法启动
　　检查 node -v ≥ v22.5.0；确认 8787 端口未被占用（ss -ltn | grep 8787）；查看
　　启动日志是否有异常堆栈；确认数据目录可写。
　　5.1.2 数据显示为空
　　确认页面已嵌入 /wa.js；浏览器 F12 → Network 查看是否存在对 /api/collect 的
　　POST（成功应返回 204）；上传的站点与统计服务跨域时确认反向代理已转发
　　X-Real-IP（IP 为空不影响计数，仅影响按 IP 的限流与匿名指纹强度）；检查仪表
　　盘时间范围（days 参数）是否覆盖数据时间。
　　5.1.3 客户端 IP 识别异常
　　服务使用 X-Real-IP → X-Forwarded-For 首段 → 套接字地址的顺序取值。部署在
　　反向代理后请务必透传 X-Real-IP，否则所有访客将显示为代理 IP，导致独立访客
　　计数偏低。
　　5.1.4 数据库体积过大
　　设置 WA_RETENTION_DAYS 启用自动留存，或执行 npm run prune -- --days=90 手动
　　清理；仍不满足可对 events 表执行 VACUUM（reclaim 已删页）。

5.3 安全与合规建议
　　· 对外部署务必置于 HTTPS 与反向代理之后；控制台与审计接口如需不对外暴露
　　　可在代理层按路径 / IP 白名单限制；
　　· 密钥文件 .wa_secret 与数据库必须同备份、同恢复；泄露密钥不影响已存数据
　　　的正确性，但会削弱历史访客匿名性（建议泄露后更换盐并接受计数基线变化）；
　　· 建议启用 WA_RETENTION_DAYS 并定期 npm run prune，践行《个人信息保护法》
　　　最小化存储原则；审计报告可在站内“隐私政策”页面引用，即「/api/audit」；
　　· 上报脚本不含 cookie，无需弹窗同意；但如站点已接入第三方统计/广告，请
　　　自行评估整体合规口径。
